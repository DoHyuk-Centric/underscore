# 밑줄 — 급등 종목 AI 진단 개선 로그

급등 상위 10개 종목의 AI 진단을 개선하면서, 버전마다 무엇을 바꿨고 결과가 어떻게 달라졌는지 기록한다. 새 버전을 확인할 때마다 아래 [다음 기록 양식](#다음-기록-양식)에 맞춰 맨 아래에 이어서 적는다.

**결과 수치가 아니라 "왜 그렇게 판단했는지, 뭘 착각했다가 고쳤는지"가 궁금하면 [AI-진단-회고.md](./AI-진단-회고.md)를 먼저 보는 게 낫다.** 그 문서는 다음 프롬프트를 쓸 때 참고할 체크리스트도 정리해뒀다.

## 결과 파일과 비교 페이지

- 버전별 진단 원문은 `docs/ai-diagnosis-log/{버전}-{기준일}.json`에 보관한다. 형식은 `{ version, title, baseDate, recordedAt, storage: "db" | "dry-run" | "manual", diagnoses: [...] }`이고, `diagnoses`의 각 항목은 조회 API 응답(`StockDiagnosis`)에 `model`을 더한 것이다. 사람이나 모델이 직접 조사해 만든 목표치는 `version: "target"`, `storage: "manual"`로 둔다.
- 웹 개발 서버(`pnpm --filter web dev`)에서 `/dev/diagnosis-compare`를 열면 두 버전을 골라 10종목을 항목별 또는 실제 카드 모양으로 나란히 비교할 수 있다. 기준일이 같으면 같은 종목끼리, 다르면 같은 순위끼리 짝짓는다. 기본 선택은 최신 버전과 같은 기준일의 목표다.
- 이 폴더에 파일을 추가하거나 지우면 개발 서버를 다시 켜지 않아도 선택 목록에 바로 반영된다(`apps/web/vite.config.ts`의 `watch-diagnosis-log`). 비교 페이지는 배포 빌드에 포함되지 않는다.

## 현재 파이프라인 (v2 기준)

```text
매일 14:10 KST 크론 또는 서버 시작
  → 급등 상위 10개 종목 조회 (KRX)
  → 종목마다 순서대로
      ├─ 네이버 뉴스 검색 (NAVER API HUB, "특징주"·"주가" 2개 검색어)
      ├─ DART 회사 개요 (설립일, 최근 정기보고서 "사업의 개요")
      └─ DART 공시 원문 (기준일 -3일 ~ +3일)
  → Gemini 구조화 출력 (flash → 503/429면 flash-lite)
  → 형식·금지 표현 검증, 실패 시 최대 3회 재시도
  → stock_diagnosis 테이블에 (종목코드, 기준일) 단위로 저장
```

| 구성 | 위치 |
| --- | --- |
| 프롬프트 | `apps/api/src/stock-diagnosis/diagnosis.prompt.ts` |
| 출력 스키마·금지 표현 | `apps/api/src/stock-diagnosis/diagnosis.schema.ts` |
| 생성·저장·조회 | `apps/api/src/stock-diagnosis/stock-diagnosis.service.ts` |
| 뉴스 검색 | `apps/api/src/stock-diagnosis/naver-news.client.ts` |
| DART | `apps/api/src/stock-diagnosis/dart.client.ts` |
| Gemini | `apps/api/src/stock-diagnosis/gemini.client.ts` |
| 조회 API | `GET /market-data/popular/diagnoses` |
| 화면 | `apps/web/src/features/stock-detail/components/AiDiagnosisCard.tsx` |

## 평가 기준

버전을 비교할 때 같은 기준일 데이터로 아래 항목을 센다.

| 지표 | 의미 |
| --- | --- |
| 명확한 급등 이유 | 공시·기사로 확인된 구체적 사건을 headline에 제시한 종목 수 |
| 테마 가능성 | 구체적 사건 없이 테마·업종 흐름을 "가능성"으로 제시한 종목 수 |
| 미확인 | "뚜렷한 공시나 뉴스는 확인되지 않았어요"로 답한 종목 수 |
| `companyIntro` 채움 | 회사 소개가 null이 아닌 종목 수 |
| `impactContext` 채움 | 이슈 규모 비교 설명이 null이 아닌 종목 수 |
| 공시 근거 | DART 공시를 근거 링크로 단 종목 수 |
| 생성 실패 | 재시도 후에도 저장하지 못한 종목 수 |
| 소요 시간 | 10종목 전체 생성 시간 |
| 품질 문제 | 어색한 문장, 모순, 근거 오인용, 사실과 다른 내용 |

위 "명확한 급등 이유 / 테마 가능성 / 미확인"은 사람이 읽고 분류한 값이다. 비교 페이지 요약의 "공시·뉴스 부재 명시"는 헤드라인에 "공시·뉴스가 없거나 확인되지 않았다"는 표현이 있는지로 자동으로 센 값이라, 테마 가능성을 제시하면서 "공시가 없는 가운데"라고 쓴 경우도 포함된다.

## 목표 — 직접 조사한 목업 (2026-09-27 기록)

- 기준일: 2026-09-17 (v1·v2와 다른 날, 겹치는 종목은 SH에너지화학 하나)
- 결과 위치: `docs/ai-diagnosis-log/target-20260917.json`. AI 파이프라인 이전에 화면에 쓰던 목업(`apps/web/src/features/stock-detail/mock/ai-diagnosis-mock.ts`, 커밋 `803b470`)을 옮긴 것이다.
- 작성 방식: 기사 원문, 공시, 회사 자료를 사람이 직접 찾아 읽고 작성했다. 뉴스 링크는 종목마다 2건 안팎으로 골랐다.

진단 품질의 목표치로 쓴다. 기준일이 달라 비교 페이지에서는 같은 순위끼리 나란히 놓고, 내용이 얼마나 풍부한지와 문체를 비교한다.

### 목표의 특징

- **회사 소개**: 설립 연도, 주력 사업, 최근 사업 변화(예: 바닥재 사업 정리)까지 담는다.
- **이슈 규모 설명**: 4종목에 평균 226자. 계약 금액을 자회사·그룹 매출과 각각 비교하거나("자회사 매출의 14.9%, 그룹 기준 1% 남짓"), 파이프라인의 희소성("전 세계 결핵백신 후보 15종 중 하나")을 설명한다.
- **시황**: 코스피·코스닥 지수 값과 같은 테마 동반 급등 종목을 구체적으로 적는다.
- **주의**: 평균 127자. 종목 고유의 위험을 짚는다(관리종목·상장폐지 가처분, 신주 납입 전 단계, 한 매체 단독 보도, 회사 공식 사업과 테마의 불일치).

### 발견한 문제

1. **정보량 부족**: 기사 요약 한두 줄만으로는 회사 소개와 "계약이 매출의 몇 %" 같은 규모 설명을 채울 수 없다. 프롬프트가 "모르면 null"을 지시하므로 비어 있는 것은 의도대로지만, 목업보다 내용이 크게 빈약했다.
2. **어색한 문장**: HT로보틱스 headline에 "보조 보도되었습니다". lite 모델에서 주로 나타났다.
3. **모순**: 아스플로 headline이 "공시는 확인되지 않았어요"라고 한 뒤 "기관 투자자의 매수세가 유입되며 급등"이라고 원인을 단정했다.
4. **과부하**: `gemini-3.5-flash`가 503을 반복해 같은 모델 재시도가 소용없었다.
5. **오판 기록**: SH에너지화학의 "와이즈플래닛컴퍼니 회전율 260%" 기사를 처음에 무관한 기사로 판단했으나, 요약에 "SH에너지화학은 회전율 12.37%로 41위… 23.11% 급등"이 실제로 있었다. 여러 종목을 묶은 시황 기사였고 인용은 틀리지 않았다.

DART 연동 중 실제 응답에서 발견해 함께 고친 것:

- 일부 정기보고서에서 "사업의 개요" 첫 등장이 목차("2. 주요 제품 및 서비스 ---- 12")였다. 목차 패턴이면 다음 등장 위치를 찾도록 했다. (쓰리빌리언, 삼기에너지솔루션즈)
- 일부 공시 본문이 `<style>` CSS로 시작해 발췌 1,200자를 낭비했다. 스타일·스크립트 블록을 제거했다.
- 임원 거래계획보고서 같은 정형 공시가 근거 후보를 차지했다. 제외 목록에 추가했다.
- 조회공시 답변은 급등 다음 날 이후에 나오는 경우가 많아 조회 기간을 기준일 +3일까지 넓혔다.

- 회사 소개는 목표 수준에 도달했다.
- 가장 큰 차이는 **주의 문구**다. 목표는 종목 고유의 위험을 짚는데, v2는 "변동성이 커질 수 있으니 유의하세요" 수준의 일반론이 많다.
- **이슈 규모 설명**은 수치가 담긴 공시가 있을 때만 채워진다. 목표는 회사 규모 대비 비율이나 업계 내 위상까지 설명한다.
- **시황**은 지수 값을 입력으로 주지 않아서 프롬프트 규칙("자료에 없는 지수 수치를 만들지 않는다")대로 비어 있다.

### 검증한 것

- 티엔엔터테인먼트의 "합의금 90억 원"은 DART `횡령ㆍ배임혐의진행사항`(2026-09-22) 원문에 "합의금 총 90억원을 18개월에 걸쳐 분할하여 지급"으로 있는 것을 확인했다. 모델이 지어낸 수치가 아니다.

### 남은 문제

1. **flash 무료 한도가 작다**: 하루 누적 약 20회 성공 뒤부터 429가 났다. 무료 등급의 `gemini-3.5-flash` 일일 한도는 약 20회로 보인다. 10종목 × 재시도를 감안하면 대부분 `flash-lite`가 생성하게 된다.
2. **lite 결과의 주의 문구가 단조롭다**: "변동성이 커질 수 있으니 신중하게 접근하세요" 수준에 그치는 경우가 많다. (쓰리빌리언, 토마토시스템)
3. **`impactContext`는 수치가 담긴 공시가 있을 때만 채워진다**: 이번 10종목 중 공급계약 같은 수치 공시가 있는 종목이 없었다. 구조적 한계이며, 비교 기준으로 시가총액을 입력에 넣으면 "합의금이 시가총액의 몇 %" 같은 설명이 가능해진다.
4. **`[공시]` 표기 혼동**: 파이온엑스 근거 중 "[공시] 국영지앤엠·서울반도체 '공매도 금지'…"는 DART 공시가 아니라 제목이 "[공시]"로 시작하는 뉴스 기사다. DART 링크와 구분되지 않는다.
5. **생성 후 나온 공시가 반영되지 않는다**: SH에너지화학 조회공시 답변 기한은 2026-09-28이다. 한 번 저장된 진단은 다시 생성하지 않아서, 답변 공시가 나와도 진단이 갱신되지 않는다.

## 운영 메모

- **NAVER 검색 API**: 2026-07-31부로 개발자센터(`openapi.naver.com`) 신규 발급이 종료되고 NAVER API HUB(NCP)로 이관됐다. 호출 주소 `naverapihub.apigw.ntruss.com/search/v1/news`, 헤더 `X-NCP-APIGW-API-KEY-ID` / `X-NCP-APIGW-API-KEY`. 하루 25,000회 무료.
- **Gemini 무료 등급**: 한도는 분당(RPM·TPM)과 일일(RPD)로 걸리고 월 단위 한도는 없다. `gemini-3.5-flash`는 하루 약 20회에서 429가 관찰됐다. `gemini-2.5-flash`는 신규 사용자에게 제공되지 않는다(404). Google 검색 그라운딩은 결제 등록 전에는 쓸 수 없다(429).
- **DART 오픈API**: 하루 20,000회. 종목코드→고유번호 매핑(`corpCode.xml`, 상장사 약 4,000건)은 하루 한 번 메모리에 불러오고, 회사 개요는 종목별로 메모리에 보관한다. 10종목 기준 하루 호출량은 약 70회.
- **재생성**: 서비스는 이미 저장된 (종목코드, 기준일)을 건너뛴다. 같은 기준일을 새 버전으로 다시 저장하려면 해당 행을 지워야 한다.
