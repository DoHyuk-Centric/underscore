# 밑줄 — 휴장일 다음 날 종목 검색 결과 없음

## 문제 정의

2026-09-28(월) 오전, 홈 화면에서 "삼성"을 검색하면 "검색 결과가 없어요"만 나왔다.

- 검색어를 종목코드 "005930"으로 바꿔도 결과가 없었다.
- 실행 중인 API에 직접 요청해도 두 검색어 모두 빈 배열이 돌아왔다.

  ```bash
  curl "http://localhost:3000/market-data/search?q=삼성"   # []
  curl "http://localhost:3000/market-data/search?q=005930" # []
  ```

특정 검색어가 아니라 **모든 검색어에서 결과가 0건**이었다. 그래서 검색 로직(`includesHangulFuzzy`)이 아니라, 검색 대상인 종목 목록 자체가 비어 있는 문제로 보고 원인을 좁혔다.

## 원인

종목 검색은 서버 메모리에 올려둔 전체 종목 목록(`StockStore`)을 걸러서 결과를 돌려준다. 이 목록은 서버가 시작될 때 한 번, 그리고 매일 14:00 KST에 공공데이터포털의 KRX 상장종목 정보 API로 채운다.

문제는 이 API를 **항상 "어제" 날짜 하루로만** 조회했다는 점이다.

```ts
// apps/api/src/stock-search/clients/krx-listed.client.ts (수정 전)
basDt: getYesterdayKstBasDt(),
```

이 API는 장이 열리지 않은 날짜를 요청하면 에러 없이 **빈 목록**을 돌려준다. 2026-09-28 전후를 직접 조회한 결과는 다음과 같다.

| 기준일 | 요일 | 비고 | 종목 수 (`totalCount`) |
| --- | --- | --- | --- |
| 2026-09-27 | 일 | 주말 | 0 |
| 2026-09-25 | 금 | 추석 연휴 | 0 |
| 2026-09-24 | 목 | 추석 연휴 | 0 |
| 2026-09-23 | 수 | 영업일 | 2,755 |

월요일의 "어제"는 일요일이라 0건을 받았다. 이때 `StockSearchService.refresh()`는 "종목 데이터가 비어 있습니다" 에러를 로그에만 남기고 목록을 채우지 않는다. 서버가 막 시작된 상태라 기존 목록도 없었으므로, 결국 **빈 목록으로 모든 검색을 처리**하게 됐다.

한 문장으로 정리하면 다음과 같다.

**기준일을 "어제" 하나로 고정해서 휴장일 다음 날에는 빈 데이터를 받았고, 그 상태에서 서버가 시작되면 다음 갱신 때까지 종목 목록이 비어 있었던 것이 근본 원인이다.**

### 영향 범위

- 주말이나 공휴일 다음 날, 서버가 새로 시작된 경우에 발생한다. 이미 목록이 채워져 있던 서버는 갱신에 실패해도 이전 목록을 그대로 써서 드러나지 않는다.
- 다음 갱신(14:00)에도 "어제"가 휴장일이면 계속 비어 있다. 이번처럼 일요일이나 연휴 다음 날이면 그다음 영업일 14:00까지 검색이 되지 않는다.
- 개발 환경에서는 API가 코드 저장 때마다 다시 시작되므로(`start:dev` 감시 모드) 주말과 연휴 내내 재현된다.

### 비슷한 문제를 이미 해결한 곳

인기 종목과 인기 섹터는 같은 문제를 겪고 `apps/api/src/common/market-data/load-latest-trading-items.ts`에서 먼저 해결해 두었다. 어제부터 하루씩 거슬러 올라가며 주말은 건너뛰고, 데이터가 있는 날을 찾을 때까지 최대 10일을 조회하는 방식이다. 종목 검색만 이 방식을 쓰지 않고 있었다.

## 해결 방법

"데이터가 있는 가장 최근 영업일 찾기"를 받아오는 데이터 종류에 상관없이 쓸 수 있는 함수(`loadLatestBaseDateItems`)로 분리했다. 인기 종목·섹터와 종목 검색이 모두 이 함수를 쓴다.

### 수정 전

```ts
// apps/api/src/stock-search/clients/krx-listed.client.ts
async fetchListedInfo(): Promise<KrxListedInfoItem[]> {
  const response = await axios.get(KRX_API_URL, {
    params: {
      // ...
      basDt: getYesterdayKstBasDt(),
    },
  });
  return response.data?.response?.body?.items?.item ?? [];
}

// apps/api/src/stock-search/stock-search.service.ts
private async refresh(): Promise<void> {
  try {
    const items = await this.krxListedClient.fetchListedInfo();
    const stocks = this.krxStockMapper.toStocks(items);
    if (stocks.length === 0) throw new Error('종목 데이터가 비어 있습니다.');
    this.stockStore.replace(stocks);
  } catch (error) {
    this.logger.error('종목 목록 갱신 실패', error);
  }
}
```

기존 `loadLatestTradingItems`는 이 함수를 감싸는 한 줄짜리 함수가 되었고, 인기 종목·섹터의 동작은 그대로다.

### 왜 이렇게 하면 해결되는가

기준일을 "어제"로 고정하지 않고 **실제로 데이터가 있는 가장 최근 영업일**을 찾아 쓰기 때문에, 주말이나 연휴 다음 날에도 직전 영업일의 종목 목록으로 채워진다. 상장 종목 목록은 하루 이틀 사이에 거의 바뀌지 않아서, 직전 영업일 기준 목록으로 검색해도 문제가 없다.

이번 경우에는 9/27(일)과 9/26(토)을 건너뛰고, 9/25와 9/24(추석 연휴, 0건)를 거쳐 9/23 목록 2,755건을 사용한다. 수정 후 같은 요청으로 "삼성" 검색 결과 21건이 돌아오는 것을 확인했다.

## 재발 방지

- `load-latest-base-date-items.spec.ts`에 단위 테스트 2개를 추가했다.
  - 시스템 시간을 2026-09-28(월)로 고정하고, 9/25 → 9/24 → 9/23 순으로 조회해 9/23 데이터를 찾는지 확인한다. 주말(9/26, 9/27)은 조회하지 않는다.
  - 10일 안에 데이터가 없으면 `null`을 돌려주는지 확인한다.
- KRX 데이터를 날짜로 조회하는 새 기능을 만들 때는 `getYesterdayKstBasDt()`를 직접 쓰지 말고 `loadLatestBaseDateItems`를 쓴다.
