# 밑줄 — 데이터 모델

## 핵심 결정 — lot 단위 + FIFO

분할 매수/매도를 **허용**한다. 다만 평균단가 방식으로 합치면 "3번 나눠 산 3개의 근거 중 뭐가 맞았는지"를 알 수 없어져 제품 철학이 무너진다.

그래서 **lot(로트) 단위**로 관리한다.

> **lot 하나 = 밑줄 하나**

| 규칙 | 내용 |
| --- | --- |
| 매수 1건 | lot 1개 생성. **각 lot에 근거(thesis) 1개가 붙는다** |
| 추가 매수 | 근거를 **또** 받는다. 물타기도 하나의 판단이므로 오히려 좋은 학습 재료 |
| 매도 | FIFO — 오래된 lot부터 소진 |
| 리뷰 | lot이 **전량 소진**될 때 그 lot에 대해 1건 생성 |
| 부분 소진된 lot | 리뷰 없음 |
| 보유기간 판정 | **lot 단위**로 계산. 1일 미만이면 리뷰 미생성 |

이렇게 하면 분할을 허용해도 근거↔결과 대응이 1:1로 유지된다. 화면에서도 "이 종목에 밑줄 3개"처럼 보여줄 수 있어 제품이 더 선명해진다.

## 엔티티

```
user
 └ account          가상 현금 잔고
     ├ lot          매수 1건 = lot 1개
     │   ├ thesis   근거 (1:1, 불변)
     │   ├ fill[]   이 lot을 소진시킨 매도 기록
     │   └ review   전량 소진 시 1건
     └ sell         매도 주문 1건 (여러 lot을 가로질러 소진 가능)
```

### `thesis` — 근거

| 필드 | 비고 |
| --- | --- |
| `id` | |
| `type` | 실적 / 모멘텀 / 테마·뉴스 / 차트 / 이유 없음 |
| `memo` | 한 줄 서술 |
| `created_at` | |

### `lot`

| 필드 | 비고 |
| --- | --- |
| `id` | |
| `symbol` | |
| `qty` | 최초 매수 수량 |
| `remaining_qty` | FIFO 소진에 따라 감소 |
| `buy_price` | 매수 시점 실제 체결가 |
| `bought_at` | |
| `thesis_id` | 1:1 |
| `status` | `OPEN` / `PARTIAL` / `CLOSED` |

### `sell` / `fill`

`sell`은 사용자의 매도 주문 1건. `fill`은 그 매도가 어느 lot을 얼마나 소진했는지 기록 (`lot_id`, `sell_id`, `qty`, `price`).

### `review`

| 필드 | 비고 |
| --- | --- |
| `lot_id` | 1:1 |
| `metrics` | 계산층 산출값 (JSON) |
| `narrative` | LLM 서술 |
| `created_at` | |

`metrics`에 들어가는 것: 손익, 벤치마크 대비 상대수익, 보유기간, 보유기간 중 고저점 대비 매도 위치, 최대낙폭, 매칭된 공시.

### `disclosure`

DART 공시. `symbol`, `date`, `type`, 원문, 쉬운 요약.

## CRUD 규칙 — 제품 철학이 코드로 굳는 지점

| 엔티티 | 규칙 |
| --- | --- |
| `thesis` | **Create / Read만.** 수정·삭제 불가 — 사후 수정이 가능하면 대조 자체가 무의미해진다 |
| `lot` | Create만. 매수 취소 없음 |
| `sell` | Create만. 매도 취소 없음 |
| `review` | 시스템 생성. 사용자는 Read만 |
| `position` | **저장하지 않는다.** lot에서 파생 계산 |

## 계산층 입력 소스

| 값 | 출처 |
| --- | --- |
| 매수가·매도가 | 자체 기록 (체결 시점 실제 시세) |
| 보유기간 중 고가·저가, 최대낙폭 | 토스 `GET /api/v1/candles` (일봉) |
| 벤치마크 대비 상대수익 | 토스 `GET /api/v1/market-indicators/{symbol}/candles` (KOSPI/KOSDAQ) |
| 공시 매칭 | DART Open API |

## 부작용과 대응

- **lot을 잘게 쪼개 단타** → 기존 "1일 미만 미평가" 규칙을 lot 단위로 적용하면 그대로 막힌다
- **lot 수 폭증** → 종목당 lot 수 상한을 두는 것을 검토 (미결정)
