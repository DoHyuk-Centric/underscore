# 밑줄 — 약관·법무

## 결론 (1차 MVP 범위 결정)

**1차 MVP는 AI 솔루션(판단 리플레이) 제공에만 집중한다.** 실시간 시세 조회 가능 여부는 1차 MVP의 필수 조건이 아니다. 형태는 웹뷰 또는 독립 웹앱이며, 기술스택(React+Vite `apps/web`, NestJS+Fastify `apps/api`, pnpm 모노레포)은 기존 스캐폴딩을 그대로 사용한다.

시세 데이터를 어떻게 조달할지(사용자 직접 입력 / 공공데이터 일봉 / 추후 유료 라이선스)는 1차 MVP 이후 과제로 미룬다. 아래는 그 판단에 이르기까지 확인된 제약 사항 기록이다.

## 토스증권 Open API — 제3자 제공 금지

토스증권 측 공식 회신(이메일):

> "토스증권 Open API는 개인투자목적으로 본인께서 이용하시는 것이 아닌, 제3자 제공은 모두 불가합니다."

### 해석

- 허용되는 것은 **계정 소유자 본인이 직접, 본인의 투자 판단을 위해 이용하는 것**뿐이다.
- "제3자 제공"은 조회 주체가 누구인지와 무관하게, **최종적으로 발급 당사자가 아닌 다른 사람이 그 데이터를 보게 되는 순간** 성립한다. 조회 빈도(실시간/1회성)나 조회 범위(전체 필드/현재가 하나)를 줄여도 이 구조 자체는 바뀌지 않는다.

### 폐기된 방안

| 방안 | 구조 | 폐기 사유 |
| --- | --- | --- |
| **플랜 A** | 운영자 키 하나로 서버가 조회해 모든 사용자에게 제공 | 정면으로 "제3자 제공"에 해당 |
| **플랜 B** | 사용자가 자기 키를 발급받아 우리 서버에 등록, 서버가 대리 호출 | 계정 소유자 본인이 아니라 서버(제3자)가 이용하는 구조라 마찬가지로 "제3자 제공"에 해당. 별도로, 사용자의 인증정보(주문 권한 포함)를 제3자가 대리 보관하는 패턴은 2020년 신용정보법 개정으로 금지된 "스크래핑 방식 마이데이터"와 구조적으로 동일 — 보안·규제 리스크가 UX 비용보다 훨씬 큼 |

### 예외 — 개인 단독 사용

사용자 본인 한 명만 자신의 계정으로 실시간 데이터를 조회·이용하는 경우(다른 사람에게 재배포하지 않음)는 위 제약과 무관하게 허용된다. 단, **다른 사람이 실제로 로그인해서 그 데이터를 조회하게 하는 순간 다시 "제3자 제공"이 성립**하므로, 포트폴리오 공개는 시연 영상/스크린샷으로 한정한다.

## TDS(Toss Design System) — 라이선스 미명시

`@toss/tds-mobile`, `@toss/tds-mobile-ait` 패키지를 npm 레지스트리와 실제 tarball에서 직접 확인한 결과:

- `package.json`에 `license` 필드 없음
- `LICENSE` 파일 없음
- `README` 없음

패키지명의 `-ait`(Apps In Toss)가 시사하듯, 이는 일반 오픈소스가 아니라 **앱인토스 파트너 개발자를 위한 배포 채널**로 보인다. 라이선스 미명시 패키지는 저작권법상 기본값이 "이용 허락 없음"이므로, 앱인토스 배포를 전제하지 않는 독립 배포에서 TDS를 쓰는 것은 의도된 사용 범위를 벗어난다.

→ TDS는 파트너 개발자를 위한 배포 채널이므로, **앱인토스 미니앱으로 배포하는 한 정당한 사용 범위 안**이다. `design/tds-preview`를 1차 MVP 개발의 기반 시안으로 그대로 사용한다.

## 앱인토스 배포 — 1차 MVP부터 진행

앱인토스 배포를 막았던 것은 TDS가 아니라 시세 재배포 제약이었다. 시세를 서버에서 토스 API로 조회해 여러 사용자에게 보여주는 구조만 쓰지 않으면(= 사용자 직접 입력으로 대체) 재배포 문제 자체가 발생하지 않는다.

**결론: 앱인토스 + TDS로 1차 MVP를 지금 배포한다.** 핵심 기능은 AI 솔루션(판단 리플레이)이고, 매수/매도 가격은 사용자 직접 입력으로 대체한다. 정교한 시세 연동(실시간·지연시세 등)은 이후 과제로 미룬다.
