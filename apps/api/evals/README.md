# AI 답변 평가 (게이트)

AI 답변에 영향을 주는 코드(프롬프트, 입력 자료, 외부 클라이언트)를 바꾸면, 고정된 시나리오로 답변을 여러 번 받아 기준을 통과하는지 확인합니다. PR에서는 `.github/workflows/ai-eval.yml`이 자동으로 돌립니다.

```bash
pnpm --filter api eval            # 게이트 실행 (Gemini 호출, 시나리오 × EVAL_RUNS회, 기본 3)
pnpm --filter api eval:capture    # 고정 입력 다시 받기 (Gemini 호출 없음)
pnpm --filter api eval:rescore    # 최근 결과를 현재 기준으로 다시 채점 (Gemini 호출 없음)
```

## 합격 기준

시나리오마다 **필수 기준을 모든 회차가 통과**하고, **점수 기준 평균이 80% 이상**이어야 합격입니다. 기준은 `trade-review/criteria.ts`에 있고 버전(`CRITERIA_VERSION`)을 붙여 관리합니다.

| 필수 기준 | 확인 방법 |
| --- | --- |
| 생성 성공 | 재생성 후에도 답을 받지 못하면 실패. 한도 초과(429)는 결과에 따로 표시 |
| 요약에 부호 붙은 수익률·손익 | 서버 계산값과 같은 표기("-14.23%", "-1,160,000원")가 요약에 있음 |
| 숫자 근거 | 답변의 금액·비율(%·%p·원·억·조)이 모두 Gemini에 보낸 입력에 있던 숫자 |
| 인용 원문 | 큰따옴표 안 10자 이상 문장이 입력에 그대로 있음 |
| 비교 기준 | "첫 매수가 대비", "평균 매수가 대비" 뒤의 %가 그 기준으로 계산한 값 |
| 미작성 근거 | 근거 없는 거래가 있으면 이유를 추정하지 않았다고 밝힘 |
| 공시 없음 | 보유 기간 공시가 없으면 없다고 밝힘 |
| 기사 출처 | 기사를 "확인된 사실"의 출처로 쓰지 않음 |
| 금지 표현 | 매매 권유·예측·전략 표현 없음 |

점수 기준은 `trade-review/scenarios.ts`의 시나리오별 기대 항목(공시 핵심 수치, 근거 원문 인용, 비교 수치, 실적 이유 등)입니다.

## 기준이나 입력을 바꿀 때

- **기준을 바꾸면** `CRITERIA_VERSION`을 올리고, 이전 결과를 `EVAL_RESULT_FILE=<결과.json> pnpm --filter api eval:rescore`로 다시 채점해 같은 기준에서 비교합니다.
- **고정 입력을 다시 받으면** 기사 검색 결과가 바뀔 수 있어, 그 커밋에서 게이트를 한 번 돌려 기준선을 다시 확인합니다.
- 모델은 기본 `gemini-3.5-flash-lite`로 고정합니다. 무료 등급에서는 과부하(503)로 실패한 호출도 하루 횟수(모델당 20회)에 들어가는데, flash는 과부하가 잦아 게이트를 끝까지 못 돌리는 날이 많았습니다. 서비스는 flash가 먼저 답하므로, 머지 직전이나 프롬프트를 크게 바꿨을 때는 `EVAL_GEMINI_MODEL=gemini-3.5-flash`(CI는 직접 실행에서 모델 선택)로 따로 확인합니다. 과부하면 다른 모델로 넘어가지 않고 기다렸다가 다시 시도합니다.
- Gemini 하루 한도는 구글 프로젝트·모델 단위입니다. 서비스와 한도가 겹치지 않도록 **다른 프로젝트에서 발급한 평가용 키**를 로컬은 `.env`의 `EVAL_GEMINI_API_KEY`, CI는 Secrets의 `GEMINI_EVAL_API_KEY`에 둡니다. 없으면 서비스 키로 평가하고 경고를 남깁니다.
- 결과는 `trade-review/.results/`(git 제외)에 JSON과 요약이 남고, CI에서는 작업 요약과 아티팩트로 남습니다.
